\chapter{Deployment and cross-dialect verification}\label{ch:22}
\section*{The working problem}
Make paths, dependencies and evidence explicit before distributing an embedding.

The four source files are pinned in vendor. MetaML standard-library discovery checks environment, installation-relative and fallback paths. Import resolution and callback capabilities should be tested under the same deployment layout users will receive.

\section*{Pinning sources and evidence}
The vendor directory contains byte-identical copies of the four uploaded sources under canonical filenames so their internal include and import names work. SOURCE-MAP.md records hashes and the original names. This is a source-pinned guide, not a claim about future releases with the same version string. Rerun examples whenever either library changes and investigate changed results before updating a golden fixture.

\section*{Chapter review: Pinning sources and evidence}
C++ examples are compiled together for fast validation and remain separate standalone programs. The D examples are source-reviewed but not compiler-validated in this environment. The build tools expose a separate D test target and report a missing compiler as a limitation rather than a pass. texlua builds the book without requiring Python; Python is used only for optional example generation, validation and development reports. The pre-generated LaTeX sources are sufficient for normal builds.
