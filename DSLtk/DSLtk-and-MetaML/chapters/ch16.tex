\chapter{Type inference and records}\label{ch:16}
\section*{The working problem}
Use inferred types as a design aid while keeping public contracts explicit.

The checker implements Hindley-Milner-style inference with numeric constraints and row-polymorphic records. Public embeddings still need application checks for ranges, units and data-dependent invariants.

\section*{Inference mechanics and API types}
TypeNode represents variables, constructors, functions, rows and other inferred structure. The unifier records links, performs occurs checks and supports rollback or commit bookkeeping. Generic variables are instantiated at use sites. Numeric constraints prevent an arithmetic function from being mistaken for a completely unconstrained polymorphic identity. TypePrinter is a presentation layer over this graph.

\section*{Chapter review: Inference mechanics and API types}
Rows let a selector require one field while retaining an unknown remainder. A closed record construction and an open record parameter are different type situations. Public embedding functions should still enforce units, ranges and resource identities that are not expressed by the inferred type. Type aliases improve readability but do not automatically create distinct runtime representations. When a domain needs an abstract type, use module signatures and the implemented ascription semantics deliberately.
