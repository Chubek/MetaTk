\chapter{Case study II: a reloadable decision service}\label{ch:24}
\section*{The working problem}
Embed MetaML as a typed policy layer while retaining host control of data, capabilities and publication. A policy receives native facts through a narrow interface and returns a decision.

A candidate session is prepared separately, checked with acceptance fixtures and published only after validation. Evaluation failure produces an application error rather than an implicit allow. Existing sessions remain alive until in-flight work completes. The standalone C++ and D programs demonstrate candidate validation without requiring an external standard library.

\section*{Policy service publication contract}
The complete decision example validates that allow applied to an Int has Bool type and checks both accepted and rejected fixtures. A candidate returning the wrong type or the wrong boundary decision is rejected. The active session is replaced only after all checks pass. A deliberately bad candidate demonstrates that the previous generation continues working after reload failure.

\section*{Chapter review: Policy service publication contract}
The sample is a synchronous service core, not an HTTP daemon or a concurrent policy server. A production adapter needs request ownership, timeouts, process containment where appropriate and a strategy for retiring old sessions after in-flight work finishes. Avoid embedding request text into source. Either register typed fact callbacks with per-request ownership or call a prepared function through a documented value bridge. Preserve an explicit error outcome instead of turning every interpreter failure into an unexplained denial.
