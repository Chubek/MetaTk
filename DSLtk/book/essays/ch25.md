## Rule identity and callback timing in the C++ snapshot

C++ `PEGDefinition` stores local rules in a vector. A reference returned by
`add_rule` can be invalidated by a later insertion. Configure a newly inserted
rule immediately, and reacquire pointers from `rules()` only after the
definition has finished growing if those pointers must be retained. Parent
definitions are borrowed and must also outlive derived definitions and their
matchers. The D port uses reference objects for rules, so appending rules does
not relocate the previously allocated rule object.

An ignored channel controls token routing, not a universal prohibition on
callbacks. In `PEGDefinition::parse`, an ordinary matching rule's configured
action can run even when its channel is ignored. A tokenizer that wants no
whitespace callback should simply give its ignored whitespace rule no action.
The matcher has its own ignored-input skipping path; its behavior should be
read separately rather than inferred from the whole-input parse driver.

The pattern compiler's exclamation mark is postfix on an atom. It does not
introduce general recursive negative lookahead syntax. `must_fail` is another
mechanism again: it negates the whole rule and consumes a character on a
successful negation. These three ideas--postfix atom negation, whole-rule
negation, and `peg_not` over parsers--must remain distinct.
