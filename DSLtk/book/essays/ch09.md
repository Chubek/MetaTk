## Snapshot contract: intended algebra and an instantiation defect

The member operator bodies studied in this chapter encode conjunction,
disjunction, and negation, but the supplied C++ implementation does not compile
ordinary expressions such as `a & b`. Inside `Predicate<F>`, the expression
`Predicate{new_lambda}` names the current specialization through the injected
class name. It does not deduce a fresh specialization for the new lambda's
distinct closure type. The constructor still expects the original `F`.
This was reproduced with the companion `projects/header-probes.cpp`.

Consequently, composition examples in the inherited implementation discussion
are source-study examples of the intended interface, not verified executable
programs against this snapshot. Calling an individual predicate works. The
following application-level composition also works because deduction takes
place in the namespace-level `dsl::predicate` factory:

```cpp
#include "DSLtk.hpp"
#include <cassert>
int main() {
  auto positive = dsl::predicate([](int x) { return x > 0; });
  auto even = dsl::predicate([](int x) { return x % 2 == 0; });
  auto both = dsl::predicate([positive, even](int x) {
    return positive(x) && even(x);
  });
  assert(both(4) && !both(3) && !both(-2));
}
```

This wrapper preserves the short-circuit semantics the member operator was
intended to provide. Its captures own copies of the predicates; references
captured by those predicates remain references. The D version implements
composition using separate concrete helper structs and does not share this
particular C++ lookup defect. Its negation spelling is `~p` or `p.negated()`.

The conceptual material below remains valuable because it shows the Boolean
algebra, capture semantics, and interface design. Its practical limitation
must remain visible: recognizing a sound algorithm in source code does not
establish that the template instantiations expressing it are well formed.
