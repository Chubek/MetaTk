## The actual matcher, rather than its name

`pattern` is a constexpr recursive predicate. It does not compile a Thompson
NFA and does not offer search, captures, grouping, alternation, escape classes,
or a question-mark quantifier. Its public operation is `matches`, and success
requires consumption of the whole input. Constant evaluation is possible when
the call occurs in a constant-expression context; ordinary runtime calls still
execute the matcher.

The two repetition branches have different algorithms. Star first tries zero
occurrences, then one, then two, retrying the remaining pattern each time.
That is increasing-length trial, not a longest-first greedy search. Plus
requires one occurrence, consumes maximally, and tests the remainder once. It
does not give characters back. A trailing dollar sign is a literal input byte;
the leading caret is skipped when encountered at the current pattern suffix.
These facts are visible directly in `match_here`.

```cpp
#include "DSLtk.hpp"
static_assert(dsl::pattern<"[0-9]+">::matches("123"));
static_assert(!dsl::pattern<"[0-9]+">::matches("123abc"));
static_assert(dsl::pattern<"a*ab">::matches("aab"));
static_assert(!dsl::pattern<"a+ab">::matches("aab"));
static_assert(dsl::pattern<"abc$">::matches("abc$"));
static_assert(!dsl::pattern<"abc$">::matches("abc"));
int main() {}
```

A sequence of overlapping stars can explore many divisions of the input.
There is no general quadratic upper bound in the pattern length and input
length together. Prefer simple classification patterns here. For grouping,
alternation, byte escapes, negated classes, and longest-prefix matching, use
the distinct `StaticRegex` facility discussed in Chapter 32.
