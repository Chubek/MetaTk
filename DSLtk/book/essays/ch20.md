## The identical-payload limitation is observable

The C++ `Result` stores a `std::variant<T,E>` and queries it by type rather
than by alternative index. `holds_alternative<T>` and `get<T>` require that
`T` occur exactly once. For `Result<std::string,std::string>`, construction
through an explicit index is possible but `is_ok`, `is_err`, and extraction
are ill formed when instantiated. Disabling the duplicate converting
constructor does not repair these queries.

Keep success and error types distinct, including after `map` and `map_err`.
A transformation from `Result<int,std::string>` to
`Result<std::string,std::string>` introduces the same problem later in a
chain. An application-specific error wrapper is often a better boundary:

```cpp
#include "DSLtk.hpp"
#include <cassert>
struct Error { std::string message; };
int main() {
  auto value = dsl::Result<int, Error>::from_ok(21)
      .map([](int x) { return std::to_string(x * 2); });
  assert(value.is_ok() && value.unwrap() == "42");
}
```

The C++ `Ok` and `Err` helpers are independent aggregates, not converting
constructors of `Result`. The D version supplies tagged constructors and an
explicit Boolean success discriminator, so identical payload types work
there. Chapter 24 explains the consequences for the C++ task API, which fixes
both payload types to string. The reference exposition below describes the
combinator model; same-type examples are construction or source-analysis
examples, not a supported queryable result in this C++ snapshot.
