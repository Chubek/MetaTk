## Evaluation is structural; array fusion is a separate claim

The C++ implementation stores operands by value and evaluates them recursively.
`BinExpr::eval` creates local evaluated operands and applies `Op{}`. If these
values are large vectors whose arithmetic operators allocate, intermediate
vectors may still be allocated. The source contains no element-index loop
that fuses a whole C++ array expression. Calling this structure lazy is
accurate; promising allocation-free vector evaluation is not.

The D implementation adds an indexed protocol with `length`, `eval_at`, and
element-wise operand access. That protocol can evaluate a combined expression
one element at a time into a single result array. The distinction illustrates
why a port should be compared by mechanism rather than advertised feature
name. Scalar C++ evaluation remains a useful, compact expression-template
example even without the D extension.

Unary expressions also require care. C++ installs arithmetic on the host and
free binary operators with `BinExpr` on the left, but it does not provide the
same complete operator family on `UnaryExpr`. The underlying unary node can
evaluate correctly while a particular chained surface expression is rejected.
Examples of richer chaining should therefore be treated as extension sketches
unless their exact operand types fit the installed overloads.
