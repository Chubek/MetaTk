# 9. MetaVM, tracing, and backend contracts

## Generic virtual machine

`metavm::VM<Instruction, ISA>` is independent of MetaIL. Define an instruction
type and an ISA with a static execution function. `ISA::register_count` is
optional and defaults to 16.

```cpp
struct TinyInstruction { bool stop = false; };
struct TinyISA {
    static constexpr std::size_t register_count = 4;
    template<class Machine>
    static bool execute(Machine& vm, const TinyInstruction& instruction) {
        if (instruction.stop) return false;
        vm.reg(0) = metavm::Value::integer(7);
        return true;
    }
};
using TinyVM = metavm::VM<TinyInstruction, TinyISA>;
```

The handler returns true to continue or false to halt. Call `trap(message)` for
an error. If the handler does not call `set_pc`, the VM advances by one.
Explicitly setting the PC to its current value is a real self-loop, not a
request to fall through. This distinction is essential for step-limit safety.

## Programs and loading

`Program<Instruction>` owns `code`, optional `source_map`, and `name`.
`source_at(pc)` safely returns a pointer only when a map entry exists.
`Builder<Instruction>` provides generic `emit`, `name`, and rvalue `finish`.
This generic builder is separate from `metail::Builder`, which also understands
IL labels and verification.

`load(program)` resets PC, steps, status, diagnostic, stack, registers, hot-loop
counters, recorded traces, compiled traces, and active recording. Output sinks
and trace subscriptions belong to the VM instance and remain configured.
The program accessor is const: changing live code behind compiled traces would
invalidate their assumptions. Load a new program instead.

## State and value access

Statuses are `Ready`, `Running`, `Halted`, `Trapped`, and `StepLimit`.
`step()` attempts one instruction and returns whether execution remains running.
`run()` loops until a terminal status. Calling it again does not magically
restart a halted program; call `load` to reset execution.

The VM exposes checked register access, stack access, options, PC, step count,
and an optional diagnostic. `set_pc` accepts indices through the exact end of
the program; a greater index throws and becomes an instruction trap when raised
inside a handler. Generic ISAs are responsible for bounding direct mutations
of the exposed stack and applying their own operand/type checks.

`Value` supports empty, integer, floating, boolean, and pointer kinds. Typed
accessors reject mismatches. `as_floating` also accepts an integer conversion.
Values are not automatic garbage-collected objects: pointer lifetime belongs
to the application. Mutating the public tag/union into inconsistent states is
a caller programming error.

## Output hooks

`set_output_sink(function<void(const Value&)>)` installs a host callback.
`output(value)` synchronously delivers a value if a sink is configured. MetaIL's
`print` calls this hook; `metail::run` uses it to capture integer output. A host
using `metail::VM` directly may instead stream output, collect it, or leave the
sink unset to discard it explicitly.

Output callbacks execute inside instruction dispatch. Standard exceptions
become VM traps, just like exceptions raised by the instruction handler. Do
not re-enter the same VM or replace its program from a callback.

## Interpreter limits

`VMOptions::max_steps` defaults to 10,000,000. Each attempted instruction counts,
including halt and runtime traps. The budget is checked before another
instruction executes. A self-loop reaches `StepLimit`, not an accidental halt.

MetaIL additionally uses `max_stack_values`, default 1,000,000, on pushes and
calls. This limit does not make arbitrary custom ISA implementations safe if
they bypass it via direct `stack()` mutation. The generic VM cannot infer the
semantics of an arbitrary instruction type.

## Trace collection

Enable `collect_trace` to emit instruction events and collect hot loops.
`hot_threshold` defaults to 64 backward branches to an entry; zero is treated
as one. Self-edges count as backedges. A trace starts at a hot target, records
the actual subsequent instruction PCs, and ends on a return to its entry or at
`max_trace_length` (default 256, effectively at least one).

`max_traces`, default 1024, caps completed recordings. Trace events include
instruction, recording start/completion, compilation, native entry/exit, and
abort/failure categories. A partially recorded path that exits the program is
not a completed trace eligible for compilation. Trace collection is passive;
enabling it does not switch execution to native code.

Subscribe through `TraceBus` by listener reference or callback. `clear()` drops
all subscriptions and `size()` reports the count, which is useful for scoped
observers that reuse one long-lived VM. Subscriptions are snapshotted for each
emitted event. Listeners must outlive borrowed
subscriptions. Observers should not modify VM execution state or re-enter
dispatch. Listener exceptions outside an instruction's guarded dispatch, such
as explicit compile-event delivery, follow the application's exception policy.

An instruction-event listener that calls `trap` aborts the attempt before the
instruction handler runs, rather than executing the instruction with an
already-trapped machine state.

## JIT extension protocol

`JitBackend<VMType, Instruction>` defines:

* `compile(vm, program, trace, diagnostic)` -> owning `unique_ptr<CompiledTrace>`;
* `execute(vm, compiled, next_pc, diagnostic)` -> whether native execution ran.

`CompiledTrace` has a virtual destructor and stores trace ID and entry PC. A
backend can derive from it to retain executable-memory ownership and metadata.
`compile_trace(backend, trace_index)` compiles one completed trace and caches it
at the entry. Compilation exceptions are converted to compile-failed events.
`try_execute_compiled(backend)` explicitly attempts a cached entry. It checks
terminal states, the outer dispatch budget, and the returned PC. Native backend
exceptions trap the VM.

A backend must enforce instruction budgets within its own native trace. The
generic VM counts one successful native dispatch, not an unknown number of
native instructions. A backend that returns false must not leave speculative
register/stack/PC changes behind. It must honor traps and use a matching
compiled-trace representation; mixing unrelated backend objects is invalid.

Executable allocation, W^X transitions, instruction-cache synchronization,
calling convention, unwind registration, guards, side exits, and lifetime
management are backend responsibilities. No default method pretends to compile
machine code. MetaChain's built-in native path is the separate ahead-of-time
Linux backend described in chapter 11.
