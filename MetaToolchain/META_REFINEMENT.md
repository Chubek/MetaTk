# Meta* refinement — first verified batch

## API additions and behavior changes

- `metajit::MethodBasedJIT` is now implemented in the formerly empty
  `MetaJIT/MethodBasedJIT.hpp`: `register_method`, typed `get`, and `compiled`.
  It owns lazily compiled executables, detects recursive compilation, validates
  entries before publication, and permits retry after failure. This is a trusted
  machine-code compiler cache, not a new MetaIL frontend. Ownership, exceptions,
  platform support and synchronization are documented in `MetaJIT/README.md`.
- MetaLD C++ string-taking methods now reject embedded NULs rather than silently
  passing truncated names/paths to C. No C ABI change.
- No existing public signatures were changed. No required dependency was added.

## Directory audit

The scope is the seven immediate subdirectories beginning with `Meta`, excluding
generated build trees. This is a first refinement batch, not a claim that every
possible defect or missing feature has been eliminated.

| Directory | Finding and work in this batch |
| --- | --- |
| `MetaIL` | Registered analyses/transforms are real implementations; their catch-all "unimplemented" errors reject unknown kinds. Replaced conservative global-name dead-assignment scanning with CFG-based backward liveness. |
| `MetaJIT` | Four headers were empty. Implemented the method cache; tracing, OSR and deoptimization remain unresolved below. Also fixed locale-dependent generated byte lists. |
| `MetaAS` | Existing C/C++ assembler embedding implementation is not a stub. Exercised API, DSL, example and integration coverage; no speculative feature additions. |
| `MetaLD` | Existing implementation delegates to the real linker. Hardened C++ string boundaries and move-assignment teardown order; expanded embedding regressions. |
| `MetaArchIR` | Existing portable-assembly builder/parser is not an optimizer or instruction selector. Exercised API, CLI and all registered examples; no feature claims expanded. |
| `MetaArchDB` | Generated data, not executable stubs. Verified all 28 DSL models against their source YAML and backend links. No generated/spec data edited. |
| `MetaVM` | Both nested directories are empty. Added an explicit status/requirements document rather than inventing bytecode semantics. |

## Fixes and regressions

### MetaIL

Dead assignments now use live-variable propagation across actual CFG successors,
including back edges and joins. Discardable dead RHS reads do not keep arbitrary
dead dependency chains alive. The old 64-round cutoff is gone. An overwritten
assignment can be removed even when the same variable is used later; calls and
potentially trapping RHSs become `eval`, preserving their inputs and effects.

`MetaIL/tests/test_dead_assignments.lua` covers overwrite elimination, retained
calls/division traps, a join's necessary definition, loop-carried definitions,
a 200-definition dead chain, and inputs needed by a discarded assignment's call.
Existing kernel files and generation rules are unchanged.

### MetaJIT

`MetaJIT/tests/method.cpp` covers lazy compilation/reuse and execution, invalid
registration, duplicate/unknown methods, compiler failure/retry, signature
failure/retry, recursive compilation, missing entries, and stable published code.

The preprocessing emitter now uses the classic locale: digit-grouping locales
could previously turn a byte such as `243` into `2,4,3`, silently changing the
generated machine code. A custom numeric-locale regression verifies byte-identical
generated C++ without requiring an installed locale package.

### MetaLD

All C++ string arguments passed to C are checked for embedded NULs, including
input paths, memory input names, host symbols, lookups, output paths and entry
names. Move-assignment destroys the old linker before its resolver captures,
matching the owner-before-callback teardown rule already used by MetaAS.
`tests/test_embedding.cpp` tests each string boundary, verifies rejected inputs
leave collection state intact, and links successfully through a moved resolver.

### Reproduce

From this directory, with the sibling dependencies described in the project
READMEs available:

```sh
cmake -S MetaIL -B MetaIL/build
cmake --build MetaIL/build --parallel 4
ctest --test-dir MetaIL/build --output-on-failure -j 4
MetaIL/build/metail verify

cmake -S MetaJIT -B build-metajit-check -G 'Unix Makefiles' \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_FLAGS='-Wall -Wextra -Wpedantic -Werror' \
  -DCMAKE_CXX_FLAGS='-Wall -Wextra -Wpedantic -Werror'
cmake --build build-metajit-check --parallel 4
ctest --test-dir build-metajit-check --output-on-failure -j 4

cmake -S . -B build-meta-check -G 'Unix Makefiles' \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_FLAGS='-Wall -Wextra -Wpedantic -Werror' \
  -DCMAKE_CXX_FLAGS='-Wall -Wextra -Wpedantic -Werror'
cmake --build build-meta-check --parallel 4
ctest --test-dir build-meta-check --output-on-failure -j 4
python3 tools/compile_archdb.py --check --tool build-meta-check/metaarch
```

For Clang use separate build directories with `-DCMAKE_C_COMPILER=clang
-DCMAKE_CXX_COMPILER=clang++`. For each compiler's sanitizer configuration use
Debug and append `-fsanitize=address,undefined -fno-omit-frame-pointer` to both
language flag strings. Root dependencies use the existing system-first/fetched
fallbacks; no new dependency installation policy was introduced.

## Unresolved stubs and next steps

- `MetaJIT/TracingJIT.hpp`: no interpreter/trace recorder or trace input contract
  is defined. Whole-method caching must not be presented as trace compilation.
- `MetaJIT/OSR.hpp`: no frame layout, live-value map, safepoint convention or
  interpreter-to-native transition ABI is specified.
- `MetaJIT/Deopt.hpp`: no snapshot, guard failure, side-exit or reconstruction
  contract is specified. Adding a container with this name would not implement
  deoptimization.
- `MetaVM/vmspec` and `MetaVM/vmweave`: no source or bytecode contract exists.
  `MetaVM/README.md` lists the decisions needed before an implementation.

Those facilities remain unimplemented rather than being filled with no-op
success paths. This pass does not implement SSA, memory/alias analysis, an
instruction selector, register allocation, or a VM, and does not claim the
original broader MetaArch phase-A–G maintenance brief is complete. New APIs
for the remaining facilities should follow agreed semantics and executable
conformance fixtures before further implementation.
